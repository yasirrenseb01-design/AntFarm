### ประเมินเพดาน 2,000 ตัว (วัด 2026-11-18, editor, รังตั้งต้นเพดานยกชั่วคราว, เฉลี่ย 360 ก้าว)
| มด | การจำลอง ms/ก้าว (ตู้ / ป่า) | ที่ 1× (60 ก้าว/วิ) | ที่ 5× | คำนวณย้อน 120 วัน (substep 4) |
|---|---|---|---|---|
| 500 | 0.56 / 0.42 | 3% ของเวลา | ~2.8 ms/เฟรม | ~3.5 นาที |
| 1,000 | 1.00 / 0.67 | 6% | ~5 ms/เฟรม | ~5.9 นาที |
| 2,000 | 1.99 / 1.64 | 12% | ~10 ms/เฟรม | ~10.7 นาที |
- การจำลองช้าลงตามจำนวนเป็นเส้นตรง (GDScript ทั้งหมด ยังไม่มีส่วนไหนใน C++)
- **วิวในรังวาดได้ไม่เกินเพดานกราฟิก 250/400/600 ตัว** ไม่ว่ารังใหญ่แค่ไหน — ยกเว้น `_bind_workers` ที่อ่านมดงาน**ทุกตัว** 3–4 รอบ + เรียงทุกเฟรม
  (6.4 ms ที่ 861 ตัว ใน PLAN_0.12_native_ants) → คาด ~15 ms ที่ 2,000 ตัว [อนุมาน: เส้นตรง ยังไม่วัด] = ตัวเสี่ยงที่สุด
- ข้างนอก: มดนอกรัง ~470–580 ตัวที่ 2,000 (ที่ 1,000: ~240–280) — ยังไม่ได้วัดภาพพื้นที่หากินที่จำนวนนี้
- C++ ตอนนี้มีแค่: สุ่มดินทำ mesh, หาที่พัก (settle), ตรวจดินชนตัว (bend/soil hits/gap), มองข้างหน้า — การจำลองทั้งหมดและงานภาพต่อมดส่วนใหญ่ยังเป็น GDScript
- ถ้าจะขยาย: (1) bind แบบไม่อ่านทุกตัวทุกเฟรม หรือใน C++ (2) ลูปต่อมดของการจำลองใน C++ (คาดเร็วขึ้นหลายเท่า [อนุมาน]) (3) วัดภาพข้างนอก 500+ ตัว
  (4) ขนาดเซฟ/หน่วยความจำ — ทำเป็นขั้นของตัวเองก่อนขั้น 1 ของแผนนี้ (เกณฑ์ตัวมีปีกขึ้นกับเพดาน)

### ประเมินเพดานวาด 1,400 / 1,000 / 700 (ผู้ใช้ 2026-11-18, ทำหลัง 0.14) — **[อนุมาน จากตัวเลขเดิม ยังไม่ได้วัดที่จำนวนนี้]**
- ตอนนี้ (GDScript): งานต่อมดที่วาด ~35 µs/ตัว/เฟรม (21 ms ÷ 600) + ส่วนคงที่ ~11–15 ms → 700/1,000/1,400 ตัว ≈ 40/50/64 ms (25/20/15 fps) บน CPU เครื่อง dev
- ย้ายไป C++ ตามแบบ `NestAnts` (คาดเดิม 600 ตัว: วิวรัง ~30 → 8–10 ms, เร็วขึ้น ~3–4 เท่า) → 1,400 ตัว CPU ~18–20 ms
- **การ์ดจอจะกลายเป็นตัวจำกัด:** ท่าขาคิดใน vertex shader ต่อจุดของทุกตัว — RTX 3050 ~8 ms ที่ 600 → ~19 ms ที่ 1,400 ถ้าเป็นเส้นตรง (~50 fps);
  Intel UHD ช้ากว่ามาก — **"ต่ำ 700" อาจหนักเกินเครื่องการ์ดในตัว** (ระดับต่ำมีไว้ให้เครื่องอ่อน); ต้องวัดเวลาการ์ดจอต่อตัวที่วาดก่อนตั้งตัวเลข
  (`--draw-cap=<n>` มีอยู่แล้ว แต่ต้องมีมดในรังเกินจำนวนนั้น → หลังเพดาน 2,000 ของขั้น 0.5)
- ทำภาพต่างกันตามระยะกล้องเพื่อลดงาน → ระวัง LESSONS 3u (ผู้เล่นเห็นมดเปลี่ยนท่าตอนซูม)
