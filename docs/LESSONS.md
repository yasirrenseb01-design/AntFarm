# บทเรียนจากความผิดพลาด

อ่านก่อนเริ่มงานทุกครั้ง แต่ละข้อมี **สิ่งที่พลาด → ต้นเหตุ → วิธีกันไม่ให้เกิดอีก**
ถ้าพลาดเรื่องใหม่ ให้เพิ่มข้อไว้ที่นี่ในรอบงานเดียวกัน (ไม่ใช่แค่แก้แล้วผ่านไป)

## การรันและทดสอบ

1. **Godot ค้างเป็นจอดำ** (เกิด 2 ครั้ง, v0.8.0 / v0.8.3)
   - ต้นเหตุ: สั่งเปิดเกมทั้งที่สคริปต์มี parse error (Godot ไม่ปิดเอง); ครั้งที่สองต่อคำสั่งด้วย `;` ทำให้รันแม้ตรวจไม่ผ่าน
   - กัน: เปิด Godot ผ่าน `tools/dev/gd.sh` เสมอ — ตรวจทุกสคริปต์ก่อน ถ้าพังจะบอกไฟล์และบรรทัดแล้วไม่รัน
   - parse error ที่พบบ่อย: `var x := <ค่าที่เป็น Variant>` (ต้องใส่ชนิดเอง `var x: float = ...`),
     ชื่อตัวแปรซ้ำในฟังก์ชันเดียว (`m` ซ้ำ), ใช้ค่าคงที่ของคลาสอื่นโดยไม่ preload (`Ant.SEARCH` ใน dev_tools ต้องเป็น `sim.Ant.SEARCH`)
1b. **ตัวตรวจรันทดสอบต่อทั้งที่ parse ไม่ผ่าน** (v0.8.20) — Godot ค้างจน timeout
   - กัน: `tools/check.ps1` หยุดหลังขั้น parse ถ้ามีไฟล์ไม่ผ่าน; ตัวแปรที่ได้ค่าจาก Dictionary/Variant ต้องใส่ชนิดเอง (`var d: Vector2 = ...`)
2. **ลบไฟล์เกมที่ต้องเก็บ** (เกิด 2 ครั้ง: v0.7.0, แล้ว v0.8.0 กับ v0.8.1)
   - ต้นเหตุ: ลบด้วยมือแล้วนับ "5 เวอร์ชันล่าสุด / x.y.0" ผิด
   - กัน: `tools/build.ps1` ลบเองตามกฎแล้ว — ห้าม `rm` ใน `build/versions`
   - ถ้าหายไปแล้ว: สร้างคืนจาก commit ด้วย `git worktree add` + `--export-release "Windows Desktop"`
3. **ตรวจท่าเดินจากภาพนิ่งภาพเดียว** (v0.8.0)
   - ต้นเหตุ: ภาพนิ่งบอกไม่ได้ว่าเท้าไถลไหม และมดตัวที่เลือกอาจยืนอยู่เฉยๆ
   - กัน: `--seq=9 --seq-every=3 --seq-speed=0.5 --at-ant=walker` แล้ว `python tools/dev/strip.py shots/seq/<ชื่อ>`
3b. **ตรวจความลื่นของท่าทางจากภาพห่าง ๆ** (v0.8.12: ราชินี "ตัดไปตัดมา")
   - ต้นเหตุ: ถ่ายทุก 20 เฟรม จึงไม่เห็นว่าท่ากระโดดตอนเปลี่ยนกิจกรรม และไม่เคยถ่ายแต่ละท่าจากด้านข้างเทียบกับท่าพัก
     (ทิศงอท้องกลับด้านมาตั้งแต่มีท่าต่อสู้ ไม่มีใครเห็น)
   - กัน: ท่าใหม่ทุกท่าถ่าย `--queen-act=<id>` มุมข้าง (`--pitch=0.25 --dist=16`) เทียบกับท่า 1; ช่วงเปลี่ยนท่าถ่ายถี่ (`--seq-every=3`–6)
   - กิจกรรมที่สลับกันต้องผ่าน `AntModel.act_step/act_y` (ผสมท่า) — ห้ามส่งเลขกิจกรรมตรง ๆ เข้า shader
3c. **เดาจากภาพว่ามดทำอะไร** (v0.8.14: มด "ขยับอยู่ตรงไข่กับราชินี")
   - ภาพบอกไม่ได้ว่ามดกำลังทำงานหรือติดอยู่ — ใช้ `--seq ... --trace` ดูบทบาท/กิจกรรม/ตำแหน่งทีละเฟรม
     (ครั้งนี้เห็นทันทีว่าตำแหน่งแกว่งไปมาโดยกิจกรรมเป็น "เดิน" ตลอด = ไปไม่ถึงเป้า)
   - เป้าหมายที่เป็น "กลางห้อง" ต้องคิดเสมอว่าอาจมีของ (ราชินี) ทับอยู่
3d. **กฎการจำลองที่ตั้งใจให้รังเล็ก ไปโดนรังใหญ่ด้วย** (v0.8.14 ขยายห้องราชินี: รัง 14 ตัวน้ำตาลหมด)
   - กัน: เปลี่ยนกฎการจำลองแล้วเทียบ "ก่อน/หลัง" หลาย seed ทั้งรังก่อตั้งและ `--workers=14` (คืนไฟล์เดิมด้วย `git show HEAD:<ไฟล์>`)
3e. **ตัดสินจากการวัดรอบเดียวในฉากที่สุ่ม** (v0.8.16: ค่าทับลูกมดรอบหนึ่ง 0.18 อีกรอบ 4.05 ทั้งที่โค้ดเดียวกัน)
   - ภาพในรังใช้ `randf()` (ไม่ใช่ seed) — วัดอย่างน้อย 3 รอบ × 40 เฟรม และดู "ใครเป็นคนทับ" (`--trace` แยกตามหน้าที่/กิจกรรม)
     ไม่ใช่ดูค่าเฉลี่ยตัวเดียว; ครั้งนี้แยกแล้วเห็นทันทีว่าเป็นพี่เลี้ยงที่เดินเข้ากลางกองลูกมด
3f. **ทดสอบความเร็วด้วยสถานการณ์ที่ผู้เล่นไม่เจอ** (v0.8.17–18: มด 300 ตัวยัดในรังที่เพิ่งเริ่ม 1.7 ซม³)
   - ผู้ใช้ทักว่าไม่ใช่สิ่งที่คนเล่นเจอ — รังจริงโตตามประชากร มดกระจายหลายห้อง
   - กัน: ความเร็ว/รูปทรงรังให้ทดสอบกับรังที่จำลองโตจริง (`tests/year_run.gd ... <ชื่อ>` แล้ว `--testsave=<ชื่อ> --slot=<ปี>`)
     ส่วนกรณีแย่สุด (`--workers=300 --warm=0.3`) ใช้เป็นเพดาน ไม่ใช่ตัวแทนการเล่นจริง
   - การ์ดจอ: ใช้ `--perf` ดู "gpu" ก่อนเดา; ทดลองปิดทีละส่วน (เงา / ไม่วาดมด) — ระวัง shader ที่คอมไพล์ไม่ผ่าน
     (เช่นใช้ `return` ใน vertex) จะได้ตัวเลขผิดโดยไม่รู้ตัว ต้องดู "SHADER ERROR" ในผลด้วย
3g. **วัดอาการ "กระตุก" ด้วยระยะที่ขยับต่อเฟรม** (v0.8.29: มดสลับที่ไปมาที่ 0.2×)
   - ตอนถ่ายภาพเฟรมช้า (~7 เฟรม/วินาที) มดที่เดินปกติก็ขยับ 0.5 มม./เฟรม จึงนับปนกับมดที่วาร์ปจนตัวเลขไม่มีความหมาย
   - กัน: นับ "ไปแล้วกลับ" (ขยับเกิน 0.2 มม. แล้วเฟรมถัดไปย้อนทิศ) ด้วย `--seq ... --pops`; วัดก่อน/หลังด้วยไฟล์เดิมจาก `git show HEAD:`
   - ค่าที่บวกเพิ่มทับตำแหน่งทุกเฟรม (แรงผลักกันทับตัว) ต้องจำกัดอัตราการเปลี่ยน ห้ามรีเซ็ตเป็น 0 ทันที
4. **ทดสอบความสมดุลด้วยสคริปต์ที่ป้อนอาหารให้** (v0.7.0–0.7.1)
   - ต้นเหตุ: `tests/year_run.gd` ตอนแรกเติมน้ำ/อาหารให้ตลอด จึงไม่เห็นว่าฉากป่าอยู่เองไม่ได้ (ไม่มีน้ำ, เพลี้ยไกลเกิน)
   - กัน: ทดสอบทั้งแบบดูแลและ `alone` และหลาย seed (`... alone 5`, `... alone 2`) — ดูผลหลายปี ไม่ใช่ปีเดียว
5. **การทดสอบที่ผ่านทั้งที่ผิด** (v0.7.0 save_test)
   - ต้นเหตุ: เพิ่มค่าเข้า fingerprint แต่ไม่ได้เพิ่ม `%` ในสตริง — ทั้งสองข้างผิดเหมือนกันเลย "ตรงกัน"
   - กัน: หลังแก้ test ให้ดูผลที่พิมพ์ออกมาจริงหนึ่งครั้ง ไม่ใช่ดูแค่ PASSED
6. **ผลจำลองต่างกันระหว่างเล่นต่อกับโหลดเซฟ** (v0.7.4)
   - ต้นเหตุ: แคช (`food_cell`) ไม่ถูกตั้ง dirty เมื่อค่าข้ามเกณฑ์ (เพลี้ยฟื้นน้ำหวาน)
   - กัน: ค่าที่คำนวณซ้ำได้ต้องมีจุด "ทำให้เก่า" ทุกที่ที่อินพุตเปลี่ยน; save_test ช่วยจับ — อย่าข้ามเมื่อมันล้ม
7. **ไฟล์ Blender สร้างซ้ำได้ไฟล์ไม่เหมือนเดิมทุกไบต์**
   - เป็นธรรมชาติของ Blender (ลำดับจุด) — เทียบจำนวนจุด/สามเหลี่ยมแทน และสร้างใหม่เฉพาะโมเดลที่แก้ (คืนไฟล์อื่นด้วย `git checkout`)

8a. **วัดความเร็วผิดวิธี** (v0.8.7)
   - FPS เฉลี่ยดูดี แต่ผู้เล่นรู้สึก "ไม่ลื่น" เพราะเฟรมกระตุกเป็นช่วงๆ; และการ `print` ทุกเฟรมระหว่างวัดทำให้เกมช้าเอง
   - กัน: ใช้ `--perf` (ดู p95, เฟรมช้าสุด, จำนวนเฟรม >33 มิลลิวินาที) และสะสมเวลาไว้ใน `sim.prof` แล้วพิมพ์ครั้งเดียวตอนจบ
   - เฟรมเกิน 16.7 มิลลิวินาทีนิดเดียวก็กลายเป็น 33 เพราะ VSync — งานหนักที่ไม่ต้องเสร็จในเฟรมนั้นให้ย้ายไปเธรด (WorkerThreadPool)
8b. **ระบบใหม่ครอบคลุมไม่ครบ** (v0.8.4 ตัวกันชน)
   - มดขุดวาดแยกอีกชุดจึงไม่อยู่ในระบบกันชน — กัน: ก่อนบอกว่า "แก้แล้ว" ให้ไล่ดูทุกที่ที่วาดสิ่งนั้น (`_dig_vis`, `_mates`, ราชินี, กองลูกมด)

8c. **แรงดันแยกวัตถุที่ไม่สะสม** (v0.8.4–0.8.7: มดยังซ้อนกันครึ่งตัว)
   - ต้นเหตุ: คิดแรงดันจากตำแหน่งที่ "ดันแล้ว" แต่ตั้งค่าระยะดันใหม่แทนการบวกเพิ่ม → แยกได้เฟรมหนึ่ง แรงหาย กลับมาซ้อน
   - กัน: ระบบแก้การซ้อนทับให้ "สะสม" ส่วนที่ยังซ้อนอยู่ และคลายกลับช้าๆ; วัดผลด้วยตัวเลข (ระยะใกล้สุด/จำนวนคู่ที่ซ้อน) ไม่ใช่ดูภาพอย่างเดียว

8d. **ทดสอบแค่ห้องใหญ่** (v0.8.4–0.8.8: ห้องก่อตั้งรังเล็ก มดทะลุผนัง ราชินีจมพื้น)
   - กัน: ของที่เกี่ยวกับรัง/ห้อง ให้ถ่ายภาพทั้ง **ราชินีตัวเดียวหลังมดงานรุ่นแรกออก** (`--warm=60` ไม่มี `--workers`) และรังใหญ่
   - ระบบที่ขยับตำแหน่งที่วาด (ดันแยก ฯลฯ) ต้องเช็กว่าไม่ดันเข้าดิน (`_open_at`)

8e. **ปล่อยเวอร์ชันทั้งที่ตรวจไม่ผ่าน** (v0.8.10: FPS รัง 300 ตัวเหลือ 13)
   - ต้นเหตุ: ต่อคำสั่ง `check.ps1 | tail && build && commit` — `tail` สำเร็จเสมอ คำสั่งต่อไปเลยรันแม้ตรวจล้ม
   - กัน: ใช้ `tools/dev/release.sh` (สร้างไฟล์เกมเฉพาะเมื่อเจอ "ALL CHECKS PASSED") แล้วค่อย commit หลังอ่านผล
   - ระบบที่วนลูปตามจำนวนลูกมด/มด ต้องลองกับรัง 300 ตัวก่อนส่ง (ตัวตรวจความเร็วทำให้แล้ว — อย่าข้าม)

## ความสมจริง

8. **ขนาดผิดจริงโดยไม่มีใครเห็น** (ราชินี ~12 มม. แทน ~9 มม. มาตั้งแต่ PART 5)
   - ต้นเหตุ: ใส่ตัวเลขสเกลด้วยตา (`2.3`) ไม่ได้เทียบกับขนาดจริง
   - กัน: ทุกโมเดล/สเกลต้องเทียบกับตาราง "ขนาดจริง" ใน `docs/BIOLOGY.md`; ตัวเลขสเกลเป็นค่าคงที่ที่มีคอมเมนต์ว่ากี่ มม.
9. **ใช้รูปทรงหรือค่าที่ออกแบบให้ของชิ้นหนึ่งกับของอื่น**
   - ภาพดินกลบที่ออกแบบให้จิ้งหรีดไปใช้กับตะขาบยาว 9 ซม.; ห้องทรงรีทำให้พื้นโค้งจนขาจมดิน; แมลงวันเอียงจนปีกค้ำตัวลอย
   - กัน: ก่อนนำโค้ดภาพไปใช้กับของใหม่ ให้ถ่ายภาพของใหม่ตัวนั้นดูก่อนส่ง (มุมต่ำ + มุมบน)
10. **ระบบที่ตั้งค่าตาม "สัดส่วนของความจุ"** (v0.7.3)
    - เกณฑ์เก็บน้ำตาล = 15% ของความจุ → รังใหญ่ความจุสูงมากจนไม่เคยสะสมไขมัน
    - กัน: เกณฑ์ที่เป็นสัดส่วนของสิ่งที่โตตามรัง ให้ลองคิดค่ากับรังเล็กและรังใหญ่ก่อนเสมอ
11a. **ใช้ตัวนับที่ออกแบบไว้เรื่องหนึ่งมาตอบอีกเรื่อง** (v0.8.2→0.8.6)
    - ป้าย "จำศีล" ใช้ `cold_days` (ตัวนับการพักหนาวของราชินี ซึ่งรีเซ็ตเมื่อรัง >14°C ตอนเที่ยงคืน) → ค้าง "จำศีล" ถึงเดือนพฤษภาคม
    - กัน: สถานะที่ผู้เล่นเห็นให้มีฟังก์ชันของตัวเอง (`sim.hibernating()`) และลองดูทั้งต้น/กลาง/ปลายฤดูก่อนส่ง
11. **ทำงานเฉพาะหน้าจุดเดียวแล้วจุดอื่นตามมา** (รังพรุน → แก้ → หนามห้อย → แก้ → ผนังเหลี่ยม)
    - กัน: เมื่อผู้ใช้ส่งภาพปัญหา ให้หาต้นเหตุร่วม (เช่น "ข้อมูลดินครึ่งช่อง") ก่อนแก้อาการ

## เครื่องมือและการเขียนไฟล์

12. **ข้อความไทยหรือเครื่องหมายพิเศษพังใน heredoc ของ bash**
    - ต้นเหตุ: stdin ของ Python บน Windows ไม่ใช่ UTF-8, `'` ใน heredoc
    - กัน: สคริปต์แก้ไฟล์ที่มีภาษาไทย ให้เขียนเป็นไฟล์ .py ด้วย Write แล้วรัน (`PYTHONUTF8=1` ถ้าจำเป็น)
13. **ไฟล์โตเกินกฎโดยไม่รู้ตัว**
    - กัน: ก่อนปล่อยเวอร์ชันดู `git ls-files '*.gd' '*.py' | xargs wc -l | sort -rn | head` — เกิน ~500 แยกทันที (ดู WORKFLOW)
