# บทเรียนจากความผิดพลาด

อ่านก่อนเริ่มงานทุกครั้ง แต่ละข้อมี **สิ่งที่พลาด → ต้นเหตุ → วิธีกันไม่ให้เกิดอีก**
ถ้าพลาดเรื่องใหม่ ให้เพิ่มข้อไว้ที่นี่ในรอบงานเดียวกัน (ไม่ใช่แค่แก้แล้วผ่านไป)

## การรันและทดสอบ

1. **Godot ค้างเป็นจอดำ** (เกิด 2 ครั้ง, v0.8.0 / v0.8.3)
   - ต้นเหตุ: สั่งเปิดเกมทั้งที่สคริปต์มี parse error (Godot ไม่ปิดเอง); ครั้งที่สองต่อคำสั่งด้วย `;` ทำให้รันแม้ตรวจไม่ผ่าน
   - กัน: เปิด Godot ผ่าน `tools/dev/gd.sh` เสมอ — ตรวจทุกสคริปต์ก่อน ถ้าพังจะบอกไฟล์และบรรทัดแล้วไม่รัน
   - parse error ที่พบบ่อย: `var x := <ค่าที่เป็น Variant>` (ต้องใส่ชนิดเอง `var x: float = ...`),
     ชื่อตัวแปรซ้ำในฟังก์ชันเดียว (`m` ซ้ำ), ใช้ค่าคงที่ของคลาสอื่นโดยไม่ preload (`Ant.SEARCH` ใน dev_tools ต้องเป็น `sim.Ant.SEARCH`)
1b. **ตัวตรวจรันทดสอบต่อทั้งที่ parse ไม่ผ่าน** (v0.8.20) — Godot ค้างจน timeout
   - กัน: `tools/check.ps1` หยุดหลังขั้น parse ถ้ามีไฟล์ไม่ผ่าน; ตัวแปรที่ได้ค่าจาก Dictionary/Variant ต้องใส่ชนิดเอง (`var d: Vector2 = ...`)
2. **ลบไฟล์เกมที่ต้องเก็บ** (เกิด 2 ครั้ง: v0.7.0, แล้ว v0.8.0 กับ v0.8.1)
   - ต้นเหตุ: ลบด้วยมือแล้วนับ "5 เวอร์ชันล่าสุด / x.y.0" ผิด
   - กัน: `tools/build.ps1` ลบเองตามกฎแล้ว — ห้าม `rm` ใน `build/versions`
   - ถ้าหายไปแล้ว: สร้างคืนจาก commit ด้วย `git worktree add` + `--export-release "Windows Desktop"`
3. **ตรวจท่าเดินจากภาพนิ่งภาพเดียว** (v0.8.0)
   - ต้นเหตุ: ภาพนิ่งบอกไม่ได้ว่าเท้าไถลไหม และมดตัวที่เลือกอาจยืนอยู่เฉยๆ
   - กัน: `--seq=9 --seq-every=3 --seq-speed=0.5 --at-ant=walker` แล้ว `python tools/dev/strip.py shots/seq/<ชื่อ>`
3b. **ตรวจความลื่นของท่าทางจากภาพห่าง ๆ** (v0.8.12: ราชินี "ตัดไปตัดมา")
   - ต้นเหตุ: ถ่ายทุก 20 เฟรม จึงไม่เห็นว่าท่ากระโดดตอนเปลี่ยนกิจกรรม และไม่เคยถ่ายแต่ละท่าจากด้านข้างเทียบกับท่าพัก
     (ทิศงอท้องกลับด้านมาตั้งแต่มีท่าต่อสู้ ไม่มีใครเห็น)
   - กัน: ท่าใหม่ทุกท่าถ่าย `--queen-act=<id>` มุมข้าง (`--pitch=0.25 --dist=16`) เทียบกับท่า 1; ช่วงเปลี่ยนท่าถ่ายถี่ (`--seq-every=3`–6)
   - กิจกรรมที่สลับกันต้องผ่าน `AntModel.act_step/act_y` (ผสมท่า) — ห้ามส่งเลขกิจกรรมตรง ๆ เข้า shader
3c. **เดาจากภาพว่ามดทำอะไร** (v0.8.14: มด "ขยับอยู่ตรงไข่กับราชินี")
   - ภาพบอกไม่ได้ว่ามดกำลังทำงานหรือติดอยู่ — ใช้ `--seq ... --trace` ดูบทบาท/กิจกรรม/ตำแหน่งทีละเฟรม
     (ครั้งนี้เห็นทันทีว่าตำแหน่งแกว่งไปมาโดยกิจกรรมเป็น "เดิน" ตลอด = ไปไม่ถึงเป้า)
   - เป้าหมายที่เป็น "กลางห้อง" ต้องคิดเสมอว่าอาจมีของ (ราชินี) ทับอยู่
3d. **กฎการจำลองที่ตั้งใจให้รังเล็ก ไปโดนรังใหญ่ด้วย** (v0.8.14 ขยายห้องราชินี: รัง 14 ตัวน้ำตาลหมด)
   - กัน: เปลี่ยนกฎการจำลองแล้วเทียบ "ก่อน/หลัง" หลาย seed ทั้งรังก่อตั้งและ `--workers=14` (คืนไฟล์เดิมด้วย `git show HEAD:<ไฟล์>`)
3e. **ตัดสินจากการวัดรอบเดียวในฉากที่สุ่ม** (v0.8.16: ค่าทับลูกมดรอบหนึ่ง 0.18 อีกรอบ 4.05 ทั้งที่โค้ดเดียวกัน)
   - ภาพในรังใช้ `randf()` (ไม่ใช่ seed) — วัดอย่างน้อย 3 รอบ × 40 เฟรม และดู "ใครเป็นคนทับ" (`--trace` แยกตามหน้าที่/กิจกรรม)
     ไม่ใช่ดูค่าเฉลี่ยตัวเดียว; ครั้งนี้แยกแล้วเห็นทันทีว่าเป็นพี่เลี้ยงที่เดินเข้ากลางกองลูกมด
3f. **ทดสอบความเร็วด้วยสถานการณ์ที่ผู้เล่นไม่เจอ** (v0.8.17–18: มด 300 ตัวยัดในรังที่เพิ่งเริ่ม 1.7 ซม³)
   - ผู้ใช้ทักว่าไม่ใช่สิ่งที่คนเล่นเจอ — รังจริงโตตามประชากร มดกระจายหลายห้อง
   - กัน: ความเร็ว/รูปทรงรังให้ทดสอบกับรังที่จำลองโตจริง (`tests/year_run.gd ... <ชื่อ>` แล้ว `--testsave=<ชื่อ> --slot=<ปี>`)
     ส่วนกรณีแย่สุด (`--workers=300 --warm=0.3`) ใช้เป็นเพดาน ไม่ใช่ตัวแทนการเล่นจริง
   - การ์ดจอ: ใช้ `--perf` ดู "gpu" ก่อนเดา; ทดลองปิดทีละส่วน (เงา / ไม่วาดมด) — ระวัง shader ที่คอมไพล์ไม่ผ่าน
     (เช่นใช้ `return` ใน vertex) จะได้ตัวเลขผิดโดยไม่รู้ตัว ต้องดู "SHADER ERROR" ในผลด้วย
3g. **วัดอาการ "กระตุก" ด้วยระยะที่ขยับต่อเฟรม** (v0.8.29: มดสลับที่ไปมาที่ 0.2×)
   - ตอนถ่ายภาพเฟรมช้า (~7 เฟรม/วินาที) มดที่เดินปกติก็ขยับ 0.5 มม./เฟรม จึงนับปนกับมดที่วาร์ปจนตัวเลขไม่มีความหมาย
   - กัน: นับ "ไปแล้วกลับ" (ขยับเกิน 0.2 มม. แล้วเฟรมถัดไปย้อนทิศ) ด้วย `--seq ... --pops`; วัดก่อน/หลังด้วยไฟล์เดิมจาก `git show HEAD:`
   - ค่าที่บวกเพิ่มทับตำแหน่งทุกเฟรม (แรงผลักกันทับตัว) ต้องจำกัดอัตราการเปลี่ยน ห้ามรีเซ็ตเป็น 0 ทันที
3h. **จัดวางของตาม "ลำดับในรายการ" ทุกครั้งที่อัปเดต** (v0.8.31: กองไข่สั่นจัดที่ใหม่ทุกครั้งที่มีไข่ฟัก)
   - ไข่ฟักออกจากหัวรายการ ลำดับของทุกใบเลื่อน → ตำแหน่งทุกใบเปลี่ยน; ของที่โต/วางใหม่ก็ดันของอื่น
   - กัน: ของที่ผู้เล่นเห็นนิ่งๆ ต้องจำตำแหน่งต่อชิ้น (`_placed` ด้วยป้าย `_v`) วางใหม่เฉพาะชิ้นใหม่หรือที่ใช้ไม่ได้แล้ว
     และวัดด้วย `--pops` (นับของที่ขยับเอง/จมดิน) ก่อน-หลัง
3i. **เพิ่มการตรวจต่อชิ้นในงานที่ทำซ้ำบ่อย โดยไม่ดูเวลา** (v0.8.31–34: จัดกองลูกมดช้าลง 20 เท่าในรัง 300 ตัว)
   - ตัวเลข FPS ในผลตรวจลดจาก ~40 เป็น 32 สองเวอร์ชันแล้วยังผ่านเกณฑ์ 25 เลยไม่มีใครเห็น
   - กัน: เปลี่ยนโค้ดที่รันทุกครั้งที่จัดภาพ ให้ดู `--perf` (ส่วน "brood layout" ฯลฯ) ก่อน-หลัง; ผลที่ไม่เปลี่ยนให้จำไว้
     ของที่ค้นหาแล้วไม่เจอที่ดีกว่าอย่าค้นหาซ้ำทุกรอบ; ตัวเลข FPS ที่ลดลงเกิน ~10% ให้หาสาเหตุทันที
3j. **แก้อนิเมชันจากภาพมุมเดียวหรือจากการคิดเอา** (v0.8.32–36: ราชินีเลียไข่ "ไม่โดน หน้าจมดิน" ห้ารอบ)
   - กล้องมุมคงที่เห็นแค่หลังเธอตอนหันไปหากอง; ตัวเลขตำแหน่งปากเดาเอง; ไม่ได้ดูมุมมองทะลุดิน
   - กัน (ผู้ใช้สั่ง 2026-10-13): ทุกครั้งที่แก้อนิเมชัน สร้างฉากนั้นทันที (`--anim=...`), ให้กล้องตามจุดที่สำคัญ
     (`--follow-queen`), ถ่ายถี่ๆ อย่างน้อยข้างซ้าย-ขวา หน้า บน และทะลุดิน, วัดจุดสัมผัสเป็นตัวเลข
     (ตำแหน่งจากโมเดลจริง ไม่ใช่ค่าที่เดา) แล้ววนแก้จนทุกมุมถูกก่อนส่ง
   - ภาพที่มีระนาบตัด: ขาที่ยื่นเลยขอบตัดลงไปอาจเหยียบพื้นส่วนที่ถูกตัดออก — วัดพื้นใต้เท้าก่อนสรุปว่าจมดิน
3k. **หาความช้าแค่ในโค้ดที่ตัวเองจับเวลา** (v0.8.51: FPS ลดจาก ~36 เหลือ 28 หลายเวอร์ชัน)
   - ส่วนที่หนักที่สุดไม่อยู่ในตัวจับเวลาเลย: ภาพตัดขวางรัง 2D วาดมดพร้อมขาทีละตัว ~9,000 ชิ้นต่อเฟรม
   - กัน: ดู `--perf` บรรทัด "engine" (draw calls / objects) เทียบกับรังว่าง; ถ้าเวลาเฟรมรวมมากกว่าผลรวมส่วนที่จับเวลาไว้มาก
     แปลว่าภาระอยู่ในเอนจิน (การวาด 2D/3D) ไม่ใช่สคริปต์
   - GDScript: `==` ระหว่าง Dictionary เปรียบเทียบทุกช่อง ใช้ `is_same()` เมื่อหมายถึงตัวเดียวกัน
3l. **ตัววัดที่หลวมเกินบอกว่า "ไม่มีปัญหา"** (v0.8.52: วัดมดในดินได้ 0 แต่ผู้ใช้เห็นมดจมพื้นชัดๆ)
   - จุดวัดสูงกว่าตัวมดจริง (และต้องจม 2 ใน 3 จุด) เลยไม่เคยเจอ; การซ้อนกันก็นับเฉพาะที่ซ้อนลึกมาก
   - กัน: ก่อนเชื่อตัววัด ให้ลองกับภาพที่ผู้ใช้ส่งมา (หรือฉากที่เห็นปัญหาชัด) ว่าตัววัดจับได้จริง แล้วค่อยใช้วัดก่อน-หลัง
3m. **ตรวจของที่โตได้ด้วยขนาดตอนวาง** (v0.8.55: ตัวอ่อนโผล่ทะลุผนังห้อง)
   - ตัวอ่อนวางตอนยังเล็ก (เกิดจากไข่ ขนาด ~0.3) ตรวจว่าพ้นผนังที่ขนาดนั้น แล้วโตเป็น ~1.1 ทั้งที่ห้ามขยับเอง → ปลายจมผนัง;
     จุดตรวจยังสั้นกว่าตัวจริง (หัวยาวเลยจุดตรวจ ~0.3) และความเอียงตามพื้นเปลี่ยนตามขนาด
   - กัน: ตรวจตอนวางด้วยขนาดโตเต็มที่ ใช้จุดบนผิวตัวจริงจากรูปทรงโมเดล (`mesh_kit`) และวัดด้วยตัวนับที่ครอบคลุม
     (`--trace-crowd` ตัวอ่อน/รังไหมในดิน) ในรอบที่ปล่อยเวลาเดินจนลูกมดโตจริง (`--live --speed=100`) ไม่ใช่ภาพนิ่ง
3n. **วัดก่อน-หลังด้วยรอบเดียว** (v0.8.55: มดซ้อนกันวัดได้ 3.6 ↔ 5.8 ↔ 11.5 จากรอบต่างกันของโค้ดเดียวกัน)
   - ภาพในรังสุ่มต่างกันทุกรอบ ค่าเฉลี่ยรอบเดียวแกว่งเป็นเท่าตัว เกือบสรุปผิดทั้งทางดีและทางแย่
   - กัน: เทียบเวอร์ชันเก่า (git worktree) กับใหม่ในเครื่องเดียวกันพร้อมกัน หลาย seed (≥8) แล้วค่อยสรุป;
     ถ้าค่าแย่ลง ให้แยกสาเหตุ (พิมพ์รายคู่: พักทั้งคู่/เดินผ่าน/ช่องเดียวกัน) ก่อนเดาแก้
   - การยกตัวให้พ้นดินต้องยกเฉพาะส่วนที่ "ยกแล้วพ้น" (พื้นโค้ง) — ส่วนที่ติดผนังด้านข้าง ยกเท่าไรก็ไม่พ้น
     (v0.8.54 ยกสูงสุดจนมดลอยเหนือพื้นข้างผนัง ~1–3 หน่วย) ให้หันตัวหนีแทน
3o. **ตัวนับที่จับคู่ผิดตัว** (v0.8.56: `--pops` นับมด "กระตุก" ได้ 400–800 ครั้ง ทั้งที่จริง 1–4)
   - เดิมจับคู่มดที่วาดในเฟรมก่อนกับเฟรมนี้ด้วย "ตัวที่ใกล้ที่สุด" — ในรังแน่น มดสองตัวเดินสวนกันใกล้ๆ ถูกสลับตัว นับเป็นกระตุก
   - กัน: ตัววัดรายตัวต้องติดตามด้วยตัวตน (`wid`) ไม่ใช่ตำแหน่ง; ตัวเลขที่สูงผิดปกติ ให้สงสัยตัววัดก่อนแก้โค้ด
3p. **ของที่ทำทุกเฟรมทุกตัวต้องดูตอนซูมออกด้วย** (v0.8.56: ให้ตัวแนบพื้นทำให้รัง 300 ตัวช้าลง ~5 มิลลิวินาที)
   - คิดค่าพื้นใต้ตัวทุกมุมหัน + ทุกเฟรม → แก้: คิดพื้นรอบ "ช่อง" ครั้งเดียวแล้วอ่านตามมุม, ดูซ้ำแค่ 1/3 ของมดต่อเฟรม,
     หยุดคำนวณเมื่อเข้าที่แล้ว, และทำเฉพาะมดที่อยู่ใกล้กล้องพอจะเห็น (ซูมออกมดเหลือไม่กี่พิกเซล)
3q. **ภาพทดสอบที่ถ่ายก่อนรังสร้างเสร็จ** (v0.8.57: เห็นช่องดำใหญ่ในห้อง หลงหาสาเหตุผิดทาง)
   - ผิวดินสร้างทีละส่วนข้ามหลายเฟรม `--frames=60` บางส่วนยังไม่มี → ภาพมีรูดำที่ในเกมจริงไม่มี
   - กัน: ภาพตรวจผิวดิน/หน้าตัดใช้ `--frames=600` (หรือมากพอให้คิว `_queue` ว่าง); ตอนหาสาเหตุภาพแปลก ให้ระบายสีแยกแต่ละ
     ส่วนใน shader (หน้าตัด/ผิวหน้า/ผิวหลัง) ทีละขั้น ก่อนตั้งทฤษฎี
3r. **MultiMesh ที่ไม่ได้ตั้งสีต่อชิ้น** (เส้นขอบมดที่เลือกเป็นท่ายืนตรงมาหลายเวอร์ชัน)
   - shader มดอ่านรหัสส่วนร่างกายจาก COLOR.a (สีจุด × สีชิ้น) — ชิ้นที่ไม่ได้ `set_instance_color` ได้ alpha 0 ทุกส่วนเลยกลายเป็นลำตัว
