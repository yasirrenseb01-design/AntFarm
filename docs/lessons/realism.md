# บทเรียน: ความสมจริง

สารบัญทุกข้ออยู่ที่ `docs/LESSONS.md` — เพิ่มข้อใหม่ที่นี่แล้วเพิ่มบรรทัดในสารบัญด้วย


8. **ขนาดผิดจริงโดยไม่มีใครเห็น** (ราชินี ~12 มม. แทน ~9 มม. มาตั้งแต่ PART 5)
   - ต้นเหตุ: ใส่ตัวเลขสเกลด้วยตา (`2.3`) ไม่ได้เทียบกับขนาดจริง
   - กัน: ทุกโมเดล/สเกลต้องเทียบกับตาราง "ขนาดจริง" ใน `docs/BIOLOGY.md`; ตัวเลขสเกลเป็นค่าคงที่ที่มีคอมเมนต์ว่ากี่ มม.
9. **ใช้รูปทรงหรือค่าที่ออกแบบให้ของชิ้นหนึ่งกับของอื่น**
   - ภาพดินกลบที่ออกแบบให้จิ้งหรีดไปใช้กับตะขาบยาว 9 ซม.; ห้องทรงรีทำให้พื้นโค้งจนขาจมดิน; แมลงวันเอียงจนปีกค้ำตัวลอย
   - กัน: ก่อนนำโค้ดภาพไปใช้กับของใหม่ ให้ถ่ายภาพของใหม่ตัวนั้นดูก่อนส่ง (มุมต่ำ + มุมบน)
10. **ระบบที่ตั้งค่าตาม "สัดส่วนของความจุ"** (v0.7.3)
    - เกณฑ์เก็บน้ำตาล = 15% ของความจุ → รังใหญ่ความจุสูงมากจนไม่เคยสะสมไขมัน
    - กัน: เกณฑ์ที่เป็นสัดส่วนของสิ่งที่โตตามรัง ให้ลองคิดค่ากับรังเล็กและรังใหญ่ก่อนเสมอ
11a. **ใช้ตัวนับที่ออกแบบไว้เรื่องหนึ่งมาตอบอีกเรื่อง** (v0.8.2→0.8.6)
    - ป้าย "จำศีล" ใช้ `cold_days` (ตัวนับการพักหนาวของราชินี ซึ่งรีเซ็ตเมื่อรัง >14°C ตอนเที่ยงคืน) → ค้าง "จำศีล" ถึงเดือนพฤษภาคม
    - กัน: สถานะที่ผู้เล่นเห็นให้มีฟังก์ชันของตัวเอง (`sim.hibernating()`) และลองดูทั้งต้น/กลาง/ปลายฤดูก่อนส่ง
11b. **ระบบที่ไม่เกิดเลยโดยไม่มีใครรู้** (v0.8.25 → v0.11.1: แมงมุมหมาป่าและด้วงดินไม่เคยเข้ากล่องอีกเลย)
    - ต้นเหตุ: v0.8.25 ให้ `blocked()` นับแถบริมขอบเป็นกำแพง (มดตกจากแถบกันลื่น) โดยไม่ได้นึกถึงศัตรูที่เดินเข้ามาจากนอกกล่อง;
      บันทึกยังขึ้น "แมงมุมเดินเข้ามา…" และ "ออกไปแล้ว (จับมดได้ 0 ตัว)" จึงดูเหมือนปกติ
    - กัน: เปลี่ยนกฎกลาง (สิ่งกีดขวาง ขอบ ความเร็ว) ให้ไล่ดูทุกอย่างที่เรียกใช้ ไม่ใช่แค่มด; เหตุการณ์สำคัญต้องมีตัวนับที่ทดสอบได้
      (`tests/enemy_test.gd`: ศัตรูที่ปล่อยต้องถูกมดรุมจริง) — "บันทึกขึ้น" ไม่ได้แปลว่า "เกิดขึ้นจริง"
11c. **งานจาก Cloud session ที่บอกว่า "แก้แล้ว" แต่ไม่เคยรันจริง** (v0.11.3 → v0.11.4)
    - กรอบหน้าต่างกลับมาจริง แต่ขนาดเดิมไม่กลับ: Godot นับหน้าต่างไร้ขอบที่คลุมจอเป็นโหมดเต็มจอ (mode 4) และไม่รับ
      `window_set_mode`/`window_set_size` จนกว่าจะใส่กรอบ — อ่านโค้ดอย่างเดียวไม่มีทางรู้
    - ค่าในหน้าต่าง UI ที่ "แสดง" กับค่าที่ "ส่ง" แยกกัน (`set_value_no_signal` แล้วลืมเก็บค่า) — แถบขึ้น 0% แต่รังได้ 100%
    - กัน: งานคลาวด์ที่แตะหน้าต่าง/ภาพ/Win32 ให้ session บนเครื่องผู้ใช้รันจริงก่อน merge (บันทึกสถานะหน้าต่างใน log, มีตัวเลือก dev
      ที่ทำแทนการคลิก เช่น `--leave-after`); ค่าที่ผู้เล่นเลือกใน UI ให้ตรวจที่ปลายทาง (sim) ไม่ใช่แค่ดูป้าย
11d. **ตัวเลขการจำลองจากเครื่องคลาวด์ (Linux) ไม่ตรงกับ Windows** (v0.11.8)
    - year_run ชุดเลี้ยง seed 1–2 วันที่ 420: คลาวด์รายงาน 259/159 ตัว, บน Windows ได้ 229/121 (และ v0.11.7 คลาวด์ 259/229, Windows 146/132)
      — การคำนวณทศนิยมต่างกันนิดเดียวก็ทำให้การสุ่มเดินคนละทาง
    - กัน: เทียบ "ก่อน/หลังแก้" บนเครื่องเดียวกันเสมอ (Windows: `git worktree add` เวอร์ชันเก่าแล้วรันคู่กัน); baseline ของ self-test ทำบน Windows เท่านั้น
11e. **ขนาดเดียวกันเขียนไว้หลายที่ แล้วค่อยๆ ไม่ตรงกัน** (v0.11.41–52: ตู้ใน Home 30 ซม. แต่กล่องในเกม 60 ซม.; ดินในกล่อง 2 ซม.
    แต่รังลึก 10.8 ซม.; ตู้แอนท์ฟาร์ม 30×22 แต่รังกระจก 16.5×10.8; ห้องรอบกล่องก๊อปค่าโต๊ะมาอีกชุด)
    - ต้นเหตุ: แต่ละมุมมองตั้งตัวเลขเองด้วยตา ไม่มีที่เก็บค่ากลาง — ผู้เล่นเห็นเอง ("รังมดจะไปอยู่ไหน")
    - กัน: ขนาดของตู้/กล่อง/ดิน/รัง/มด อยู่ใน `scripts/view/common/tank_spec.gd` ที่เดียว ทุกมุมมองอ่านจากที่นั่น;
      `tests/tank_spec_test.gd` เทียบกับค่าการจำลอง (กล่อง, บล็อกรัง, รังกระจก); ของใหม่ที่มีขนาดจริงให้เพิ่มลงที่นั่น ห้ามพิมพ์ตัวเลขซ้ำ
11h. **ขยายฉากทั้งฉาก แล้วค่าที่จูนเป็นเมตรพัง** (v0.11.53: ห้อง Home ขยาย 667 เท่ารอบกล่อง)
    - ไฟ: การจางตามระยะ (distance^attenuation) เกินความละเอียด → วงแสงคมบนผนังทุกด้าน; เงาไฟเป็นเส้นริ้ว; shader ที่อิงตำแหน่งโลก
      (วิวหน้าต่าง ลายฝาไม้) ผิดสเกล — กัน: shader ใช้พิกัดวัตถุ (`VERTEX`) หรือส่งเมทริกซ์ `to_room`; ไฟที่ขยายให้ถ่ายกลางคืนดูทุกครั้ง
    - กล้องที่สร้างแล้วถ่ายภาพทันทีในเฟรมเดียวกัน ภาพออกมาจากตำแหน่งเดิมของกล้อง (ตำแหน่งส่งถึงตัววาดตอนจบเฟรม) — กัน: สร้างกล้องไว้ก่อน
      (`outworld_card.prepare`) แล้วค่อย `force_draw` ตอนถ่าย
11i. **ภาพสร้างสิ่งที่การจำลองไม่มี** (v0.11.45–56: มดขนดินข้างนอกเป็นภาพล้วน — ไม่ทิ้งกลิ่น ไม่ชนใคร; ในรังดินหายไม่มีมด)
    - กัน: ทุกอย่างที่ผู้เล่นเห็นต้องมีในการจำลอง ภาพแค่วาดตาม (docs/SPECIES.md); เปลี่ยนการจำลองแล้ววัดความเร็วในรังด้วย `--perf`/`--spikes`
      — สถานะใหม่ (มดขุดรอที่ปากรัง) ทำให้โค้ดภาพที่ไม่เคยเจอสถานะนั้นค้นหาไกลทุกเฟรม (16 วินาที/เฟรม) โดย parse และเทสต์ผ่านหมด
11. **ทำงานเฉพาะหน้าจุดเดียวแล้วจุดอื่นตามมา** (รังพรุน → แก้ → หนามห้อย → แก้ → ผนังเหลี่ยม)
    - กัน: เมื่อผู้ใช้ส่งภาพปัญหา ให้หาต้นเหตุร่วม (เช่น "ข้อมูลดินครึ่งช่อง") ก่อนแก้อาการ
