# AntFarm — แผนงาน

## เป้าหมาย
เกมจำลองการเลี้ยงมดที่สมจริงที่สุดเท่าที่ทำได้ ทำทีละส่วน เริ่มจากมดดำสวน *Lasius niger* ก่อน แล้วค่อยเพิ่มสายพันธุ์อื่น

## สองโหมดการเล่น
| โหมด | เป็นอย่างไร | ผู้เล่นทำอะไรได้ |
|---|---|---|
| **Desktop (พื้นหลัง)** | รังมดรันเป็นวอลเปเปอร์อยู่หลังไอคอนบนเดสก์ท็อป กินทรัพยากรน้อย | แค่จิ้มเบาๆ เช่น จิ้มมดให้ตกใจ จิ้มหยดน้ำหวาน |
| **Game (เข้าเกม)** | หน้าต่างเกมเต็มรูปแบบ | ให้อาหาร ปรับอุณหภูมิ/ความชื้น ดูภาพตัดรัง ขยายรัง ดูสถิติ |

ทั้งสองโหมดใช้การจำลองชุดเดียวกันและเซฟไฟล์เดียวกัน การจำลองต้องเดินต่อเนื่อง และตอนที่ปิดโปรแกรมต้องคำนวณย้อนหลังให้ (offline catch-up)

## Engine
- **Godot 4.7.2** (`E:\Godot_v4.7.2-stable_win64.exe`, รุ่นมาตรฐาน GDScript ไม่ใช่ .NET)
- ในเครื่องมี `dotnet` สำหรับทำตัวช่วย Win32 แยกต่างหากได้
- โหมดวอลเปเปอร์บน Windows: เอาหน้าต่าง Godot ไปเกาะกับหน้าต่าง `WorkerW` ของเดสก์ท็อป (เทคนิคเดียวกับ Wallpaper Engine/Lively) โดยใช้ตัวช่วยเล็กๆ ที่รับ HWND จาก `DisplayServer.window_get_native_handle()`
- การจิ้มบนเดสก์ท็อป: ไอคอนเดสก์ท็อปจะบังเมาส์ไว้ ตัวช่วยต้องดักคลิกบนพื้นที่ว่างของเดสก์ท็อป (low-level mouse hook) แล้วส่งพิกัดเข้าเกม
- ทางสำรองถ้าวอลเปเปอร์มีปัญหา: หน้าต่างโปร่งใสแบบ desktop pet ที่คลิกทะลุได้ ยกเว้นตรงตัวมด

2. **[x] ทดสอบความเสถียรระยะยาว** (2026-10-10)
   - เลี้ยงดี 1 ปี (autokeep): มดงาน 14 → 78–298 ตัวแล้วแต่ seed, ราชินีรอด; ไม่ดูแลเลย: รังร่วงโรยใน ~75 วัน (รังแห้ง → ไข่ตาย → มดงานตายทีละตัว)
   - ความเร็ว: รัง 500 ตัวที่ 60× ใช้ ~0.6 วินาที/วันในเกม; ก้าวมด ~2.5 µs
   - สิ่งที่แก้ระหว่างทดสอบ: ตารางกลิ่นอาหาร, รายชื่อมดนอกรัง, ฟังก์ชันขยับมดแบบ flat, substep ตอนเร่งเวลา (ผลไม่ลำเอียงตาม substep แล้ว),

3. **[~] รังใต้ดิน 3 มิติที่มดขุดเอง** (รุ่นแรกของ 3a + 3b ใช้ได้แล้ว 2026-10-10) (ผู้ใช้ขอ 2026-10-10: ดูได้ 2 มุม = บนพื้นดิน + ภาพตัดขวาง 3 มิติทั้งรัง ซูมได้ เห็นมดขุด)
   - ดินเป็นก้อน voxel (ประมาณ 1 มม./ช่อง) แบ่งชั้น: ดินร่วนผิวบน, ดินเหนียว, ทราย; ความชื้นในดินมีผลต่อความง่ายในการขุด
   - มดขุดทีละเม็ดดิน คาบขึ้นมาทิ้งรอบปากรัง → กองดินบนพื้นผิว (เชื่อมกับภาพด้านบน)
   - กฎการขุดแบบ stigmergy: มดขุดตรงที่มีคนเพิ่งขุด (กลิ่นขุด), ห้องเกิดรอบราชินี/กองตัวอ่อน, อุโมงค์มีแนวโน้มลงล่าง
   - ปริมาตรรังโตตามจำนวนมด (อ้างอิงงานวิจัย Buhl et al. 2004 ที่พบว่ามดขุดจนปริมาตรพอดีกับประชากร); ถ้ารังแน่นเกิน ราชินีวางไข่น้อยลง
   - มดย้ายกองตัวอ่อนไปห้องที่อุณหภูมิ/ความชื้นเหมาะ (กลางวันขึ้นห้องบนที่อุ่น)
   - ภาพ: กล้อง orbit หมุน/ซูม, ระนาบตัด (cutaway) เลื่อนได้เพื่อดูหน้าตัด, มดเป็นโมเดล 3 มิติเล็กๆ (MultiMesh)
   - สลับมุมมอง บนพื้นดิน ↔ ในรัง ด้วยปุ่มเดียว ใช้การจำลองชุดเดียวกัน
   - ผู้ใช้เลือก (2026-10-10): **ทำทั้งสองแบบ** — 3a ก้อนดินธรรมชาติ (ทำก่อน) และ 3b ตู้กระจกแอนท์ฟาร์มแบบแผ่นบาง ให้ผู้เล่นเลือกตอนเริ่มรัง; ใช้ระบบ voxel และการขุดชุดเดียวกัน
   - เทคนิค: voxel 1.5 มม., mesh แบบ surface nets แยก chunk 16³ (สร้างใหม่เฉพาะ chunk ที่ถูกขุด), shader ดินแบบ triplanar + ระนาบตัดที่ระบายหน้าตัดด้วย back-face
   - เสร็จแล้ว: ดิน voxel แบบ z-major + texture 3D ให้หน้าตัด, มดขุดทีละคำแล้วคาบขึ้นไปทิ้งเป็นกองบนผิว, ห้องแบนหลายชั้นต่อกันด้วยปล่อง,

   - ความเร็ว: มุมรัง 3 มิติ ~90–120 FPS (Intel UHD), มุมพื้นดินรัง 500 ตัว ~77 FPS (มดวาดด้วย MultiMesh)

     มดเดินช้าลงตอนหนาว, มดรวมกันห้องลึกตอนหนาว, เตือนเข้า/ออกตู้เย็น, แยกตัวเลขตายมดงาน/ลูกมด (ข้อ ข/ค ที่เสนอไว้),
     รังป่าที่โตเต็มพื้นที่ยังมีปีที่ลดฮวบตอนหนาว (ลูกชุดใหญ่ปลายร้อนสะสมไขมันไม่ทัน)
8. **[ ] รังโตเต็มวัยและการบินผสมพันธุ์** (v0.8.x) — ราชินี/ตัวผู้มีปีก, วันบินหลังฝนที่อุ่นชื้น, เก็บราชินีไปตั้งรังใหม่, ราชินีแก่

## รายการค้าง (ยังไม่ทำ — เรียงตามส่วน)
- PART 3: ความชื้นในดินแต่ละจุด (ตัวอ่อนย้ายตามความชื้น); หน้าตัดตู้แอนท์ฟาร์มยังเป็นเหลี่ยมบางจุด
- PART 5: มดปีนข้ามใบไม้/กิ่งไม้/หิน (การจำลองต้องรู้ความสูงพื้น); การกลบดินยังเป็นแค่ภาพ (ยังไม่มีผลกับการเน่า/การแย่งอาหาร);
  มดช่วยกันลากขาที่หลุด; ใบถั่วบางมุมเห็นเป็นแผ่นแบน; มดในรังบางทีเดินทับฉากอนิเมชัน
- PART 6: มดรังอื่น (มดถนน *Tetramorium* ยกทัพ, Lasius รังข้างเคียง) — ศัตรูหลักในธรรมชาติ แต่ในกล่องปิดแทบไม่เกิด
  และต้องจำลองรังที่สองทั้งรัง (ผู้ใช้ถาม 2026-10-11 ผมแนะนำให้เลื่อนไปก่อน); ศัตรูบุกเข้าไปในรัง; มดลากผู้บาดเจ็บกลับรัง;
  แมงมุมกระโดด (Salticidae) ที่อยู่ในแผนเดิม; ภาพละอองสารเคมีตอนด้วงดินพ่น
- เครื่องมือ: `mesh_kit.gd` ยังมีโมเดลสำรองแบบเก่า (ลบได้เมื่อย้ายครบ)
