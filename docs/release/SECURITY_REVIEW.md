# ตรวจความปลอดภัย (PART EA-R ข้อ R8) — v0.11.15

ตรวจจากโค้ดทั้งโปรเจกต์ (main c325636 / v0.11.13) และลองจริงด้วย Godot 4.7.2 headless บน Linux (cloud session)
เทสต์ที่ใช้พิสูจน์: `tests/save_fuzz_test.gd` (อยู่ใน `tools/check.ps1` แล้ว) — ผล self-test 25 วันตรงเดิม

## สรุป

- **เกมไม่ต่ออินเทอร์เน็ต — จริง.** ไม่มี HTTPRequest / HTTPClient / WebSocket / UDP / ENet / multiplayer / `OS.shell_open`
  ในโค้ดเลย การเชื่อมต่อมีที่เดียวคือ TCP ในเครื่อง `127.0.0.1:47815` (เกมเปิดได้ทีละตัว) ตัว Godot เองก็ไม่ส่งข้อมูลออก
- **ไม่เก็บข้อมูลส่วนตัว — จริง.** สิ่งที่เขียนลงเครื่องมีแค่รังมด (รวมชื่อมดที่ผู้เล่นตั้ง), การตั้งค่า, บันทึกโหมดวอลเปเปอร์
  และ log ของ Godot ทั้งหมดอยู่ใน `user://` ไม่มีอะไรส่งออกไปไหน (รายละเอียดใน `PRIVACY.md`)
- **ที่ต้องแก้มีจริง 1 จุดร้ายแรง:** ไฟล์ `settings.cfg` ที่ถูกแก้ทำให้เกม **รันสคริปต์ที่ไฟล์ชี้ไป** ได้ — แก้แล้ว
- จุดอื่นเป็นแบบ "ไฟล์เสีย/ถูกแก้แล้วเกมแครชหรือค้าง" — แก้แล้วทั้งหมด เหลือ 2 จุดเล็กที่ไม่ได้แก้ (ดูท้ายตาราง)

ระดับความเสี่ยง: **สูง** = รันโค้ดได้, **กลาง** = ทำให้เกมแครช/ค้าง/รังพัง, **ต่ำ** = เกมทำงานผิดหรือรำคาญ
ทุกข้อต้องมีโปรแกรมหรือคนที่**เขียนไฟล์ในเครื่องผู้เล่นได้อยู่แล้ว** — ไม่มีข้อไหนทำได้จากนอกเครื่อง

## สิ่งที่ `tests/save_fuzz_test.gd` ลอง (85 กรณี, ~15 วินาที, ต้องไม่มี script error แม้แต่ครั้งเดียว)

  มด 300 000 ตัว, duty_rng ว่าง, สภาพอากาศ/ราชินี/สถิติ/บันทึกผิดชนิด ฯลฯ) → ต้องเป็น "เซฟเสีย" (หรือ "เซฟจากเวอร์ชันใหม่กว่า")
